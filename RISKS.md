# RISKS.md — open technical risks

Known risks that sit beyond the current step. Each one names the step
where it starts to matter and the plan for handling it. Remove an entry
when it has been resolved, and note how.

| # | Risk | Bites at | Plan |
|---|---|---|---|
| 1 | **Symmetry undo.** *Spiked in 4a (`CanvasSpikeUITests`, iPadOS 26.5 sim).* PencilKit's own undo works for a plain stroke (undo → 0, redo → 1). But once the mirrored copy is appended programmatically in `canvasViewDrawingDidChange`, one undo changes nothing (both strokes stay), PencilKit's undo stack is then empty, and redo does nothing. **The pair can never be undone with PencilKit's undo.** Our own stack works: a subclass of `PKCanvasView` returns a registration-disabled `UndoManager`, so PencilKit registers nothing (`pkCanUndo=0`). Each user change pushes the *previous* `PKDrawing` once, mirror included, so one undo removes both and one redo restores both. Found along the way: the Sketch canvas registers its own strokes with the window's undo manager, so it needs the same treatment. | Step 4c | **Decision for 4c:** one app-level undo history of canvas snapshots (Sketch drawing + Ink drawing + shapes + text), shared by both canvases and the Shapes/Text layers. Both canvases use the disabled undo manager. The top-bar undo/redo, and later the two/three-finger taps, call our history, never `PKCanvasView.undoManager`. Still to check in 4c: hardware-keyboard ⌘Z and the system three-finger undo swipe, which go to the responder chain's undo manager. Route them to our history or make sure they do nothing. |
| 2 | **No `PKToolPicker`.** The system tool picker exposes the pixel eraser (creates `stroke.mask`) and pressure inks, both of which break the SVG exporter. | Step 4 | Use our own tool rail only, and set `canvasView.tool` in code. Never show `PKToolPicker`. |
| 3 | **Gesture clashes.** Two-finger-tap undo and three-finger-tap redo need custom recognizers on a scroll view that already uses two fingers to pan and zoom. iPadOS also has its own three-finger edit gestures (swipe to undo, pinch to copy). | Step 4 | Use tap recognizers that require the pan to fail, and test them in the simulator and on device. If the system gestures win, the undo/redo buttons stay the main path. |
| 4 | **Layer touch routing.** *Spiked in 4a: works.* Stack = Sketch `PKCanvasView` (bottom), SwiftUI Shapes layer in a `UIHostingController` view (middle), Ink `PKCanvasView` (top). Only the active layer has `isUserInteractionEnabled`, and touches fall through the disabled layers above it. Checked with real touches: Ink draws only ink, Sketch only sketch, and a Shapes drag moves the square while nobody draws. Two-finger pan/pinch recognizers sit on the container, and the canvases' own scrolling and pinch are off. One shared viewport (zoom + offset in 1024 space) is applied to both canvases (`zoomScale`/`contentOffset`, so PencilKit renders sharp at any zoom) and to the SwiftUI layer as a transform. A pinch with each layer active zoomed everything (1.5× → 3.5×) with **0.000 pt** misalignment and no stray marks. A stroke drawn at 3.5× starts exactly under the finger (0.00 pt) and still stores `size.width` 10. | Step 4b/4c | Use this structure in `CanvasScreen`. Two details matter: (a) UIScrollView snaps `contentOffset` to device pixels, so snap the viewport offset first and give the SwiftUI layer the value the canvas really applied. Without that, the layers drifted 0.064 pt apart. (b) The SwiftUI layer's host view uses `anchorPoint = .zero` plus a zoom/offset transform, so gesture deltas arrive in canvas units. **Not covered by XCUITest:** a pure two-finger pan with no pinch, and a second finger landing mid-stroke (the spike drops the half-drawn stroke by toggling `drawingGestureRecognizer`; never exercised, `cancelled=0`). Check both by hand on the simulator and on a device. |
| 5 | **Liquid Glass on system chrome.** Building with the iPadOS 26 SDK gives system controls (sheets, bars) the glass look automatically, while DESIGN.md asks for flat surfaces. | Step 4+ | Style our own surfaces from `Theme`. If system chrome still clashes, decide then whether to add `UIDesignRequiresCompatibility`, a temporary opt-out that Apple will remove. |
| 6 | **No physical iPad yet.** The real-device half of the export gate and the Definition of done need one. Learn thresholds also need finger testing on hardware. | Step 3 (device check), 8b, 10 | Use the simulator until then. The Mac Safari check of exported SVGs is an interim stand-in, not a replacement. |
| 7 | **Font fallback in logo text.** For characters a logo font lacks (emoji, some accents), Core Text silently falls back to a system font. `GlyphPaths` follows the run font so the SVG matches the screen, but that puts system-font outlines into a logo, which the license forbids. | Step 5 | In the text tool, check every character against the chosen font (`CTFontGetGlyphsForCharacters`) and block or flag unsupported ones before they reach the canvas. |
| 8 | **Snapshot depends on PencilKit's interpolation.** `shape-and-stroke.svg` uses a straight stroke, so it's robust, but a future iOS could sample `interpolatedPoints` differently and change the bytes. | Step 9 (CI) | If CI fails only on the snapshot after a runner/Xcode bump, inspect the diff, re-record with `TEST_RUNNER_RECORD_SNAPSHOTS=1`, and pin the CI simulator runtime. |
| 9 | **Stored width for real strokes.** *Touch: resolved.* `FingerStrokeUITests` drags real touches on the simulator: a monoline tool of width t stores `size.width` t + 2 on every point (0.5 → 2.5, 8 → 10, 40 → 42) at zoom 0.371, and the export of that drawing passes the gate (IoU 0.992). So a drawn line is 2·t thick, and `LineSize.toolWidth(forSize:)` = size / 2. *Still open:* Pencil input (may store a different or pressure-varying width) and other zoom levels. | Device check, step 4c | Check with a Pencil on device using the debug screen: all points should show the same `size.width`. The 4a routing spike also draws after a pinch-zoom to check zoom independence. |
| 10 | **PencilKit's width law could change in a future iOS.** | Every iOS bump | `MonolineWidthTests` measures the real renderer and fails with the new numbers. Update the two constants, then rerun the gate. |
| 11 | **A save and reload reports monoline strokes as `.pen`.** `PKDrawing(data:)` turns `.monoline` into `.pen` (`DrawingPersistenceTests`). Points, widths, PencilKit's render and the SVG stay identical, so export is unaffected today. But a later "is this monoline?" check, or a different future render of `.pen`, would break. | Step 6 (storage) | After loading a project, re-apply `PKInk(.monoline, color:)` to every Ink-layer stroke (the test proves this restores the type with identical pixels). `testReloadReportsMonolineAsPen` fails if Apple fixes it. |
